# Render Deployment Guide

This guide walks you through deploying Soundscape to Render.

## Prerequisites

1. Render account (sign up at https://render.com)
2. GitHub repository connected to Render
3. Last.fm API key (for web app)

## Deployment Steps

### 1. Create PostgreSQL Database

1. Go to Render Dashboard → New → PostgreSQL
2. Name: `soundscape-db`
3. Database: `soundscape`
4. User: `soundscape`
5. Plan: Starter (or your preferred plan)
6. Click "Create Database"
7. **Save the connection string** - you'll need it for the server

### 2. Deploy Backend API

1. Go to Render Dashboard → New → Web Service
2. Connect your GitHub repository
3. Configure:
   - **Name**: `soundscape-api`
   - **Environment**: `Node`
   - **Build Command**: `./apps/server/render-build.sh`
   - **Start Command**: `pnpm --filter @soundscape/server start`
   - **Plan**: Starter (or your preferred plan)

4. **Environment Variables**:
   ```
   NODE_ENV=production
   DATABASE_URL=<from PostgreSQL service>
   API_BASE_URL=<auto-generated from service URL>
   WEB_APP_URL=<will set after web app is deployed>
   PORT=<auto-set by Render>
   ```

5. Click "Create Web Service"

6. **After first deploy**, update `WEB_APP_URL` with your web app URL

### 3. Deploy Web App (Static Site)

1. Go to Render Dashboard → New → Static Site
2. Connect your GitHub repository
3. Configure:
   - **Name**: `soundscape-web`
   - **Build Command**: `./apps/web/render-build.sh`
   - **Publish Directory**: `apps/web/dist`

4. **Environment Variables**:
   ```
   VITE_API_URL=<your-api-url> (e.g., https://soundscape-api.onrender.com)
   VITE_WS_URL=<your-ws-url> (e.g., wss://soundscape-api.onrender.com/ws)
   VITE_LASTFM_API_KEY=<your-lastfm-api-key>
   ```

5. Click "Create Static Site"

### 4. Update Environment Variables

After both services are deployed:

1. **Update API service**:
   - Set `WEB_APP_URL` to your static site URL (e.g., `https://soundscape-web.onrender.com`)

2. **Update Web App**:
   - Set `VITE_API_URL` to your API URL (e.g., `https://soundscape-api.onrender.com`)
   - Set `VITE_WS_URL` to your WebSocket URL (e.g., `wss://soundscape-api.onrender.com/ws`)

### 5. Run Database Migrations

After the API is deployed, run Prisma migrations:

1. Go to API service → Shell
2. Run:
   ```bash
   pnpm install
   pnpm --filter @soundscape/db db:generate
   pnpm --filter @soundscape/db db:push
   ```

This will create all tables in your PostgreSQL database.

**Note**: The build script already runs `db:generate`, so you only need `db:push` in the shell.

## Using render.yaml (Alternative)

If you prefer infrastructure-as-code:

1. Push `render.yaml` to your repository
2. Go to Render Dashboard → New → Blueprint
3. Connect your repository
4. Render will automatically create all services from the YAML file
5. Manually set `VITE_LASTFM_API_KEY` in the web app service

## Environment Variables Reference

### Backend API (`soundscape-api`)

| Variable | Description | Source |
|----------|-------------|--------|
| `NODE_ENV` | Environment mode | `production` |
| `DATABASE_URL` | PostgreSQL connection string | From database service |
| `API_BASE_URL` | Full API URL | Auto-generated |
| `WEB_APP_URL` | Web app URL for CORS | From web app service |
| `PORT` | Server port | Auto-set by Render |

### Web App (`soundscape-web`)

| Variable | Description | Source |
|----------|-------------|--------|
| `VITE_API_URL` | API base URL | Your API service URL |
| `VITE_WS_URL` | WebSocket URL | Your API service WebSocket URL |
| `VITE_LASTFM_API_KEY` | Last.fm API key | Manual (get from https://www.last.fm/api) |

## Post-Deployment

### Verify Deployment

1. **API Health Check**: `https://your-api-url.onrender.com/health`
2. **API Docs**: `https://your-api-url.onrender.com/api`
3. **Web App**: `https://your-web-url.onrender.com`

### Database Management

Access Prisma Studio (for debugging):
1. Go to API service → Shell
2. Run: `pnpm --filter @soundscape/db db:studio`
3. Access via port forwarding or Render's shell

### Monitoring

- Check logs in Render Dashboard
- Monitor database usage
- Set up alerts for service downtime

## Troubleshooting

### Build Fails

- Check build logs in Render Dashboard
- Ensure all dependencies are in `package.json`
- Verify build scripts are executable (`chmod +x`)

### Database Connection Issues

- Verify `DATABASE_URL` is set correctly
- Check database is running
- Ensure connection string includes SSL parameters if required

### CORS Errors

- Verify `WEB_APP_URL` is set in API service
- Check web app URL matches exactly (including https://)
- Review CORS configuration in `apps/server/src/index.ts`

### WebSocket Not Connecting

- Verify `VITE_WS_URL` uses `wss://` (secure WebSocket)
- Check API service supports WebSockets
- Review WebSocket server configuration

## Custom Domain

1. Go to service → Settings → Custom Domain
2. Add your domain
3. Update DNS records as instructed
4. Update environment variables with new URLs

## Cost Optimization

- Use Starter plans for development
- Enable auto-sleep for non-production services
- Monitor database usage
- Consider upgrading only when needed
